# Data used in this project

The checked-in data are the **exact 30 selected FinQA examples** used here: 10 development and 20 public test questions. FinQA is from Chen et al., *FinQA: A Dataset of Numerical Reasoning over Financial Data* (EMNLP 2021): [paper](https://arxiv.org/abs/2109.00122), [official repository](https://github.com/czyssrs/FinQA), [upstream MIT license](https://github.com/czyssrs/FinQA/blob/main/LICENSE). These are FinQA's report excerpts, not complete report PDFs. Attribution to the underlying reports remains with their original publishers.

`processed/documents.json` maps each FinQA case ID to its source filename and citable `chunks` (`id`, `text`). Chunks derive **only** from `pre_text`, `post_text`, and `table`; table rows retain FinQA `table_N` IDs and include headers. `processed/dev_questions.json` and `processed/test_questions.json` contain case IDs and question text. `labels/dev.json` and `labels/test.json` separately map IDs to the reference `exe_ans`, narrative `answer`, and `gold_ids`. Labels are for evaluation only: `app.py`, `src/data.load_document`, and `src/pipeline` do not load them. The evaluator loads labels after it obtains a prediction. Upstream `qa`, programs, gold indices, retrieved examples and model inputs are not copied into source documents.

Selection is frozen in [`../eval/dev_ids.json`](../eval/dev_ids.json) and [`../eval/test_ids.json`](../eval/test_ids.json): Python `random.Random(6201).sample` from sorted upstream IDs, with 10 dev and 20 test cases. [`../eval/data_manifest.json`](../eval/data_manifest.json) records the upstream commit, original split counts and downloaded-file SHA-256 values. To regenerate these files, run `python -m scripts.prepare_data` from the repository root with network access. The script downloads only the pinned upstream dev/test JSON into ignored `data/raw/`, then rewrites the five selected files. Compare regenerated files and manifest with the checked-in copies before accepting changes. `data/raw/` and `data/cache/` are excluded from Git; model weights are cached outside this repository.

The test questions were inspected during v1 diagnosis, so v2 results on them are an **iterative comparison**, not independent holdout performance. The demo UI shows development cases only.
